# Keel Diagram: the fence is the source, the picture is a view

A person working with you has the Keel Diagram plugin in Obsidian. They can double-click a node
in a rendered Mermaid diagram and retype its label, and the plugin rewrites that label inside
the ```` ```mermaid ```` fence — the text stays the source of truth, the picture is only a
view of it. It also generates a **workspace map** from `keel.json`.

Your side of that bargain is to write diagram fences a human can edit and a parser can find
labels in, and never to hand-write the generated map.

## Write Mermaid, not a new language

Diagrams go in a fenced ```` ```mermaid ```` block. Obsidian renders Mermaid natively. If
Mermaid cannot express what you need, that is a question for the owner, **not** an invitation
to invent a diagram DSL, embed an SVG, or reach for a picture format nobody can diff.

## Write labels that can be edited

Label editing works by finding, in the fence text, the label belonging to the node the person
double-clicked, and replacing it. Make that unambiguous:

- **Give every node an explicit id and an explicit label**: `a[Workspace root]`, not a bare
  `Workspace root` that Mermaid turns into both at once. One id, one label, one place to
  rewrite.
- **Keep each node or edge on its own line.** Do not chain a whole graph on to one line.
- **Do not repeat the same label** on two nodes in one diagram if you can avoid it. Identical
  text in two places is the ambiguity that makes an edit land on the wrong node.
- Quote a label that contains punctuation Mermaid treats as syntax — brackets, parentheses,
  quotes, a colon in some contexts. An unquoted `(` in a label breaks the render, and a diagram
  that does not render cannot be edited.
- Prefer short labels. The person will retype them.

Supported for label editing today: flowchart, sequence and class diagrams. Other Mermaid types
still render; their labels are not double-click editable, so do not promise that they are.

## The workspace map is generated

The map is a Mermaid block whose first line is:

```
%% generated by keel-diagram from keel.json; edit the manifest, not this block
```

- **Never hand-edit a block carrying that marker.** It is regenerated on command, and your
  edit is thrown away the next time.
- To change what the map shows, change what it is generated from: `keel.json`'s projects and
  repos, and the `links:` between cards. Then run *Regenerate workspace map* — or say the map
  needs regenerating and let the person run it. It is never regenerated automatically on file
  change, so a stale map is normal and harmless.
- The map is machine-neutral by decision: it never reads `binding.json` and never shows a
  checkout path. Do not add one "for convenience". Vault documents are read on machines that
  are not this one.

## Editing a diagram yourself

When you change a diagram in a note, change the text in the fence — that is all there is. Do
not reformat the whole block while you are in there: a diff that touches every line hides the
one line that mattered, and the person may have hand-tuned the layout.

## Do not

- Do not invent a diagram format, embed an SVG, or attach an image where a fence would do.
- Do not hand-edit a block with the generated marker.
- Do not put checkout paths, machine names or credentials into a diagram.
- Do not chain a graph on to one line, or reuse a label within a diagram.
- Do not claim a diagram type is double-click editable when it is not.
